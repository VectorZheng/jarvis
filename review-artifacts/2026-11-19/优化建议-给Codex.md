# Jarvis 安卓 App 体验优化建议（2026-11-19 实测版）

> 角色分工：本文档由「体验实测」产出，**实现交给 Codex**。请按 P0 → P1 → P2 顺序执行，每条都带可验收标准。
> 前一轮界面评审见 `review-artifacts/2026-10-11/Jarvis-界面动画评审.md`；本轮是**实际跑起来操作后**的复测与收敛。

## 一、实测方法与环境

- 后端：`node server/council.mjs`（9301，`/health` 返回 `{"ok":true,"version":"0.2.1"}`）。
- 前端：`cd jarvis-app && EXPO_PUBLIC_API_BASE=http://127.0.0.1:9301 npx expo start --web --port 8082`。
- 浏览器：Edge（Playwright），移动视口 **393×852** 与 **375×667**，DPR 2，headless。
- 实际操作路径：首屏 → 麦克风 → 发送 → 流式观察 → 上滑 → 等结果 → 切「今日」再回「说话」→ 换形象弹层 → 发送后立刻停止 → 小屏复测 → 长文本输入。
- 脚本与原始数据：`review-tools/run-review-2026-11-19.mjs`、`review-tools/probe-2026-11-19.mjs`；证据 `review-artifacts/2026-11-19/{*.png,metrics.json,probe.json}`。
- 标注约定：**【实测】**＝本轮量到的数字/直接观察；**【源码】**＝读代码确认；**【待验证】**＝浏览器不能代表真机，需 Android 真机确认。
- ⚠️ 首屏 `loadMs = 19.8s` 是 Metro **开发态首次打包**，不是产品指标，**不要**写进验收，也不要据此做性能结论。

## 二、本轮结论（一句话）

视觉方向（黑白极简、安静克制、单一输入入口）是对的，**不用推翻重做**；问题集中在四类：**状态会丢、延迟是人为加的、弹层不可达、结果被大舞台挤下去**。本轮只做"让它像成品、够丝滑"，不做大改版。

## 三、P0：影响可用性，必须修

### P0-1 切页返回后会话全丢【实测】

- 现象：发送后拿到 3 张卡，点「旧版今日」→ 点「说话」返回，`[data-testid^="card-"]` 数量从 **3 → 0**，输入框内容也回到演示语。
- 原因【源码】：`App.tsx:151` 用条件挂载 `tab === 'talk' ? <TalkScreen/> : <ScrollView>…`，TalkScreen 卸载即丢 `useReducer` 里的 phase/lines/cards，以及输入草稿。
- 建议（按成本从低到高，选一种即可）：
  1. 把 `TalkScreen` 的状态（reducer state、`text`、`skinId`）**提升到 `DemoScene`**，用 props 传入；
  2. 或改成**常驻挂载 + 显示切换**：talk 页始终挂载，非激活时用 `display:'none'` 或绝对定位移出可视区；
  3. 会话进行中离页必须有一致策略：**继续跑**（推荐）或明确"已停止"。
- 验收：切走再回来，卡片数不变；输入草稿保留；流式中离页再回来，进度没有重置。

### P0-2 换形象弹层被裁切且不可滚动【实测】

- 现象：393×852 下弹层高 **420**，内容高 **717**，`overflow:hidden`，**内部可滚动元素数 = 0**；`skin-upload`（从相册选图）**完全不可见**。375×667 下弹层高 **347**，内容仍 717，更严重。
- 原因【源码】：`BossSkinPicker.tsx:33` `sheetH = Math.min(height*0.52, 420)`；`:94` 外层 `Animated.View` + `:164` `sheetInner` 是普通 View，无滚动区；顶部有拖动条但没有手势。
- 建议：
  - 结构改成：**固定头部**（标题 + 关闭按钮）＋**独立 ScrollView**（形象池/相册）＋**底部安全区 padding**；
  - 高度改为 `min(height * 0.78, 640)`，内容超出时滚动；
  - 拖动条要么实现真实拖拽（跟手、可取消、松手回弹），要么**直接去掉**——不要留一个骗人的把手；
  - 选中态只做勾选 + 轻微背景变化，不播长动画。
- 验收：375×667 与 393×852 都能滚动到「从相册选图」并完整可见；无内容被截断；打开/关闭可用。

### P0-3 点弹层外区域不关闭【实测】

- 现象：`boss-skin-sheet` 高度 420、距顶 432，遮罩层存在（393×852 覆盖全屏），但点击 `(196,100)` 后弹层**仍然可见**（`dimClickCloses: false`，两次独立测试均复现）。
- 影响：用户只能靠"选一项"离开；没有关闭按钮，等于半强制选择。
- 建议：先查 `Modal` 内 `Tap`（`BossSkinPicker.tsx:93`）的 `onPress` 是否真的触发；`close()` 里的 `Animated.spring(...).start(({finished}) => finished && onClose())` **不要依赖 `finished` 才关**——动画没回调也要关。头部补一个明确的「关闭」按钮做兜底。
- 验收：点击遮罩任意空白处 300ms 内关闭；点头部关闭按钮同样关闭；Android 返回键关闭（现有 `closeRef` 机制保留）。

### P0-4 默认输入是演示语，且发送后不清空【实测】

- 现象：`defaultInputValue = "今晚想练一下，顺便看看冰箱能做啥，这周钱紧"`；点发送后 `inputAfterSend` **仍是原文**。
- 原因【源码】：`TalkScreen.tsx:150` `useState(DEMO_UTTERANCE)`；`send()`（`:266`）全程没有 `setText('')`。
- 建议：
  - 默认**空输入**，占位文案给一句引导；
  - 空态放 **2–3 个可点建议**（如「帮我安排今晚」「今晚吃什么」），点击即填入并聚焦，**只在空态出现**；
  - 发送后清空输入、把这句话作为**用户消息**显示在会话里；
  - 发送失败时**恢复草稿**并提供重试，不能让用户丢内容。
- 验收：首屏输入为空；发送后输入为空；会话里能看到自己发的那句；失败后草稿还在。

### P0-5 麦克风承诺了未实现的功能【实测】

- 现象：点击麦克风 → 出现提示「按住说话下一版接入，先打字」（`micHintShown: true`）。它占着最常用的输入位，用户会当成有效入口。
- 建议：本轮**直接隐藏**麦克风；真正接入录音后再放回，并实现录音/取消/结束/权限拒绝四个状态。
- 验收：主路径不存在"点了才知道不能用"的入口。

### P0-6 延迟是人为叠出来的（丝滑感第一杀手）【实测＋源码】

- 实测：点发送 → 首条头头回应 **1.9s**，第一张卡 **7.4s**。
- 延迟来源【源码】：
  - `TalkScreen.tsx:273` `setTimeout(..., 900)`：**发请求前先空等 900ms**；
  - `sseClient.ts:11` `pace_ms: 900` 传给服务端，服务端按 `pace` 停顿（`server/talk.mjs:101`）；
  - `useTypewriter`（`TalkScreen.tsx:129`）：`30ms/2字`，普通行停留 280ms、`reason` 900ms、`boss` 700ms；积压超 3 行才整行直出。
  - 服务端**本身已经是流式**（`role.say` 按 6 字切片，`talk.mjs:188`），客户端又套了一层打字机 → 二次节流。
- 建议：
  1. 发送**立即**发起请求（去掉 900ms），立即给出轻量"正在处理"状态；
  2. `pace_ms` 降到 **120**（与服务端默认一致）；
  3. **删掉客户端打字机**——服务端已经逐片推流，直接渲染 `delta` 累加即可；最多给新行一个 180–240ms 淡入；
  4. 取消要能同时取消"已启动的流"和"尚未启动的定时任务"（现在是靠 900ms 定时器，去掉后这条风险自然消失）。
- 验收：点发送后 **≤100ms** 出现可见反馈；本地后端下**首卡 ≤2.5s**；无逐句强制停顿；发送后立刻停止不会在 900ms 后重新发起请求（本轮实测 `restartedAfterStop: false`，改完要重新确认这条）。

### P0-7 结果被 340px 大舞台一直挤在下面【实测】

- 现象：整段会话期间 `hero-stage` 高度**恒为 340**（采样全程 `[340]`），结果只能出现在屏幕下半部或需要滚动才能看到。
- 原因【源码】：`TalkScreen.tsx:521` `hero: { height: HERO_H }`，注释明确写"固定占位（不随会议状态收缩）"。
- 建议：同一布局里**从大标识收敛为小状态标识**——进入会商后 180–260ms 内高度收敛到约 **96px**（角色缩小居中），会话结束/回到空态再展开一次；用 Reanimated 做 `height/scale` 的连续过渡，不要两张图交叉淡入。键盘弹出时进一步让位。
- 验收：会话进行中 `hero-stage` 高度 ≤120px；结果卡片前 100ms 内即可见（不需要先滚动）；无跳变、无重影；`reduce motion` 下静态切换。

### P0-8 自动滚动抢用户控制【实测＋源码】

- 现象：流式过程中滚动容器 `scrollTop` 被持续推到 0→80→144→256（跟随到底）。
- 原因【源码】：`TalkScreen.tsx:360` `onContentSizeChange={() => { if (running) scroll.current?.scrollToEnd({animated:true}); }}` 无条件跟随；`:252` 在 `done/stopped` 后 400ms **强制滚回顶部 `y:0`**。
- 建议：
  - 只在"用户接近底部"（阈值约 80–120px）时跟随；
  - 用户上滑即**暂停跟随**，并显示「有新内容 ↓」胶囊，点击回到底部；
  - 完成后**保留当前阅读位置**，不要强制回顶。
- 验收：上滑阅读后 3s 内 `scrollTop` 不被拉回；点「有新内容」能回到底部；完成后位置不跳。

## 四、P1：原生感与细节

| 编号 | 问题 | 实测证据 | 建议 | 验收 |
|---|---|---|---|---|
| P1-1 | 麦克风 28×28、发送 30×30 命中区偏小 | 【实测】`mic {w:28,h:28}`、`send {w:30,h:30}` | 图标尺寸保持精巧，**命中区扩到 ≥44×44**（`hitSlop` 或外层容器） | 两个按钮可点区域 ≥44×44，且不与相邻控件重叠 |
| P1-2 | 输入框单行、长文本被截断 | 【实测】40 字时 `inputH: 32`，不增高 | `multiline` + `maxHeight ≈ 120` + 超出内部滚动；不挤压会话区 | 长文本可读、可换行；键盘上方始终可见发送键 |
| P1-3 | 长按换形象入口不可发现 | 【源码】`JarvisAvatar onLongPress`，无任何提示 | 从「我的」提供**可见的形象设置入口**；长按作为捷径保留 | 「我的」里能进换形象 |
| P1-4 | 主路径满是内部术语 | 【实测】会话里同时出现「会议纪要」「头头结论」「我去开会」「旧版今日」 | 见下方文案对照表 | 主路径不再出现"会商/否决/注册表/二期"等词 |
| P1-5 | 前后像两个产品 | 【源码】talk 页无 TabBar，进入"旧版今日"才出现 5 个 tab | 收敛到 **2–3 个稳定目的地**：助手 / 记录 / 我的；秘书团与习惯归入"我的"或助手设置 | 一级入口 ≤3 个，来回切换不会"换了个 App"的感觉 |
| P1-6 | 每次加载都 404 | 【实测】`404 http://127.0.0.1:9301/v1/health/snapshot`（`healthSnapshot.ts:49` 调用，服务端未实现） | 服务端补该接口返回 `{snapshot}`，或客户端在 404 时静默降级且**不打 error 日志** | 控制台无 404；无接口时静默用本地快照 |
| P1-7 | 结束态没有明确落点【待验证】 | 【实测】完成后再看，`跟进中` 与 `非医疗建议` 都没出现，但「会议纪要」还在 | 给一个明确的收尾状态（如"已安排 · 3 件事"）；`done` 后底部保留来源/免责声明 | 用户能一眼看出"这次结束了" |
| P1-8 | 无障碍与减弱动效覆盖不全 | 【源码】`useReduceMotion` 只接了部分动画；装饰头像可能形成无意义读屏焦点 | 打字机、自动滚动、短句轮换统一接入 reduce-motion；发送/停止/关闭/任务动作给准确 `accessibilityLabel`；装饰元素 `accessible={false}` | 开"减弱动态效果"后无持续呼吸/大位移/强制平滑滚动；读屏能念出状态变化 |

## 五、P2：比赛与交付（本轮不做，排期即可）

1. **Expo Router 迁移**（`AGENTS.md` 要求）：路由化后 P0-1 的"切页丢状态"从结构上消失；迁移要单独一轮，别和视觉改动混在一起。
2. **EAS 安卓构建**：`reanimated 4.5.1` + `react-native-worklets` 有原生代码，**Expo Go 跑不了**，必须 `eas build --profile development` 出开发包，再 `eas build --profile preview` 出 APK 给评委装。
3. **真机验证清单**（浏览器替代不了）：键盘避让、长输入、快速连发/停止、流式失败与重试、弹层滚动与拖拽、切页返回、前后台、减弱动效、深色、大字、读屏、实际帧率。
4. **Android 配置核对**：`app.json` 显式写 `android.softwareKeyboardLayoutMode: "resize"`；`predictiveBackGestureEnabled` 现在是 `false`，若开了要确认手势返回与 `useAndroidBack` 不打架。

## 六、明确不做（避免过度改动）

- 不推翻黑白极简视觉，不改配色体系，不加大面积渐变/模糊。
- 不引入新的重型动画库；现有 Reanimated 够用。
- 不在本轮做多页导航重构（那是 P2 的 Router 迁移）。
- 不为了"看起来丰富"往首页堆日程/天气/健康仪表盘。
- 不把未实现的能力（录音、健康同步、跨设备同步）留在主路径上当入口。
