# 演示现状与三种展示方案

核对时间：2026-11-20 11:05。以下都是当前工作区的实际状态，不是设想。

启动方式（两个终端）：

```bash

cd "D:\06_开发项目\02_AI与智能体\Jarvis" && node server/council.mjs
```

然后浏览器开 `http://localhost:8082`，窗口缩到 393×852（或按 F12 用设备模拟）。

**局限**：评委得坐到这台机器前；换台电脑就打不开；断网也打不开（首次打包要本地 Metro）。

## 二、观众现在实际看到的流程

1. 首屏：黑白极简，中间一个小管家，下面一句轻量短句，底部输入框（空）+ 两个建议：「帮我安排今晚」「今晚吃什么」。
2. 点发送后：约 **70ms** 出现第一句，**0.9 秒**内第一张结果卡落地，随后 3 张卡陆续出来（实测中位数 908ms）。
3. 过程中能看到：几件事被拆开、某个建议被另一个角色改掉（「建议调整」）、最后每件事一张卡。
4. 结束后：舞台收回成小标识，结果完整留在屏幕上；如果中途上滑，会出现「有新内容 ↓」。

一句话概括 demo 钩子：**说一句「今晚想练一下，顺便看看冰箱能做啥，这周钱紧」→ 得到一份排好序、互相不打架的今晚安排。**

## 三、三种可选的展示形态

### 方案 A：维持本机 Web 预览（0 成本，今天就能演）

- 优点：现在就能用，改一行代码就能重演。
- 缺点：必须用这台机器；是网页不是 App；手机上打开看不到（Metro 绑了 localhost）。
- 只改一点就能"多人可看"：把前端启动参数换成 `--lan`，用内网 IP（`172.17.69.137` / `10.44.194.195`）给同网段的评委手机浏览器打开。**注意**：这只是网页，不是 App，且首次加载慢。

### 方案 B：静态导出 + 内网静态服务器（约 10 分钟，仍然是网页）

```bash
cd jarvis-app
EXPO_PUBLIC_API_BASE=http://<这台机器的内网IP>:9301 npx expo export --platform web
npx serve dist -l 8080
```

- 优点：不依赖 Metro，加载快，多个设备同时看。
- 缺点：还是网页；需要这台机器开着；当前 `dist/` 是旧的，必须重新导出。

### 方案 C：EAS 出安卓包（真正的 App，推荐给比赛）

```bash
cd jarvis-app
npx eas-cli@latest init          # 生成 eas.json
npx eas-cli@latest build -p android --profile preview
```

- 优点：评委手机装 APK，直接是 App 形态；这也是"安卓 App"这个目标的实际交付物。
- 前提：Expo 账号登录；构建在云端跑，首次约 10–20 分钟。
- 注意：`react-native-reanimated` + `react-native-worklets` 有原生代码，**Expo Go 跑不了**，必须走 dev/preview build。预览包（APK）够演示用；要上架商店才用 production + AAB。
- 后端问题：APK 里写死 `127.0.0.1:9301` 在手机上指向手机自己。演示时要么把 `EXPO_PUBLIC_API_BASE` 指向这台机器的内网 IP（`http://172.17.69.137:9301`），要么让 App 无后端时走本地 mock（现有逻辑支持，`src/talk/mockStream.ts`）。

## 四、建议

- **给评委看的正式演示**：走方案 C，出 preview APK 装到一台安卓手机上，现场演一遍。
- **临时给人看一眼**：方案 A 加 `--lan`，或者方案 B。
- 无论哪种，先把 `EXPO_PUBLIC_API_BASE` 指向**内网 IP 而不是 127.0.0.1**，否则手机端拿不到后端。
